Issue No. 01

September 2026

Most of September went into CleverBound, a school boundary planning website I have been building since a college project in fall 2024. A user picks a school district and sets limits such as school capacity, and an optimization algorithm assigns neighborhoods to schools. This month I made it more secure, redesigned it, and set up backups for its database.

Build

Building happens on Saturdays, about two to three hours at a time. Everything below is from the software engineering phase of my CleverBound roadmap.

Sep 06

Set up an AI coding assistant with limits

I started using Claude Code, an AI assistant that can read and edit files on my computer, and restricted what it can access before using it on my own projects.

Why
An AI tool with file access can make mistakes or be misled by something it reads, so I wanted firm boundaries from the start.
How
Configured its permissions file to block reads outside my two project folders (one on my computer, one synced from Google Drive) and deny any edit to Git hook files. Wrote three custom skills that each generate a dated HTML log with embedded JSON metadata: one for study sessions, one for practice problems, and one for project decisions.
Result
Those logs are the source material for this page.

  • JSON
  • HTML
Sep 06

Required a pull request for every code change

I made it impossible to push code straight to the main branch of CleverBound's frontend or backend repositories, the branch that goes live, without opening a pull request first.

Why
Pull requests create a checkpoint for reviewing each change. GitHub's built-in branch protection requires a paid plan for private repositories, and I wanted the rule in place right away.
How
Wrote a Git pre-push hook in shell script for both the frontend and backend repositories. It rejects any push to the main branch and prints the steps for creating a branch and pull request.
  • Git
  • GitHub
  • Shell
Sep 12

Protected the algorithm endpoint with Cloudflare

I put Cloudflare, a service that filters incoming web traffic, in front of the part of CleverBound that runs the boundary algorithm.

Why
That endpoint is the most expensive part of the site to run, and it was publicly reachable with no protection. A bot could drive up hosting costs or take it offline.
How
Added api.cleverbound.org as a custom domain on Render, routed it through Cloudflare as a proxied CNAME with Full SSL, turned on Bot Fight Mode, and added a rate-limiting rule scoped to the /align endpoint. When domain verification failed, I queried Cloudflare's 1.1.1.1 resolver over DNS-over-HTTPS, found the record had been saved under the wrong name, and fixed it the same day instead of waiting on propagation.
Result
All production traffic to the algorithm now passes through bot filtering and a rate limit.

Sep 12

Reduced local setup to one command

Running CleverBound on my laptop used to mean exporting the backend's API key by hand and passing an extra flag so the frontend pointed at my local backend instead of the live one. Now a single command does both.

How
Renamed the frontend's environment file to .env.development so Vite's default mode points at the local Flask server, and added python-dotenv so the backend loads its API key from a gitignored .env file. Production on Render is unaffected.
  • Vite
  • Python
  • python-dotenv
Sep 20

Redesigned the website

I gave all eight pages of CleverBound and its four-step planning tool a new visual design without changing how anything works, then added layouts made specifically for tablets.

Why
The original design looked like a generic template and did not reflect what the product does.
How
Built a geography-themed look: a seamless topographic background generated with a marching-squares contour algorithm, an SVG emblem with the tagline set along a circular path, and one typeface in place of five. Then added tablet-only layouts through custom Tailwind variants that only match touch devices at least 600px wide, so phones and laptops could not pick them up.
Result
To prove the tablet layouts left everything else alone, a headless Chrome script captured every page before and after that step and compared the screenshot hashes. All 17 phone and laptop pages were pixel-identical.
  • React
  • TypeScript
  • Tailwind CSS
  • SVG
  • Headless Chrome
Sep 20

Backed up the database and created a test copy

I created a complete backup of CleverBound's PostgreSQL database, which holds its district, school, and neighborhood data, and a separate copy of it for testing.

Why
There was no way to rebuild the database if it were lost, and any testing would have touched live data.
How
Used the Supabase CLI, which wraps pg_dump, to export roles, schema, and data as three SQL files. Loaded them into a second Supabase project with psql in a single transaction, so a failed load rolls back cleanly.
Result
The production database can be rebuilt from scratch, and development runs against a realistic copy.
  • PostgreSQL
  • Supabase
  • psql
Sep 26

Tested AI assistant rules against real usage

I tightened the permissions on Claude Code, my AI coding assistant, and tested each proposed rule against how I actually use the tool before keeping it.

How
Wrote a Python hook, a script the tool runs before every file edit, that blocks edits outside my two project folders, covered by a 22-case test suite. Prototyped a similar rule for shell commands and replayed 402 commands from my own history against it.
Result
The shell rule would have interrupted normal work far more often than it caught anything, so I kept the file rule and left shell commands to the tool's built-in safety checks.
  • Python
  • Claude Code
